中文改写

李继刚写道，自己最近已经从 ChatGPT 完全切换到了 Grok Bot。他认为两边的体验差异很微妙，于是试着用「产品原子」这个视角来分析。

他把产品原子定义成：用户在这个产品里创建、命名、分享、归档、删除的最小单位。

用这个视角看 Agent，他大致分成三类。

第一类以对话为原子，也就是 session。主界面像一条按时间倒排的聊天流水，新对话不断把旧的往下推，几周前聊过的事要靠搜索才找得回来。

第二类以项目为原子，也就是 project。主界面像一个文件柜，每个抽屉装着一个项目的资料、说明和一叠对话。使用者先拉开抽屉，再在里面接着聊。

第三类以角色为原子，也就是 bot。主界面像一张组织架构图，每一个角色有职责、有记忆，和它相关的事都在同一个会话里接着聊。

他认为，产品对「原子」的不同定义，会带来体验上的一系列变化。他最想讨论的是「连续性」。

用 ChatGPT 时，从一个对话走到下一个对话，中间唯一不断的是他自己。他写道，自己就是最大的「记忆池」。

用 Project 时，资料和指令可以写入文档，一部分记忆就被让渡出去了。

用 Bot 时，连续性沉淀到了一个个 Bot 身上。

他也提到，虽然每类产品都有 Memory 功能，但同样一个词，在不同的「原子」产品里，作用差异还是很大。

如何切分各个 bot 的职责边界，他认为是以角色为原子的产品里一个很关键的课题。他建议参照 Herbert Simon 在论文《The Architecture of Complexity》中提出的近可分解性，也就是 near-decomposability：层内交互强，层间交互弱。

原文

最近从 ChatGPT 完全切换到了 Grok Bot，两者的体验差异很微妙，我尝试从「产品原子」的视角来分析下。

最近从 ChatGPT 完全切换到了 Grok Bot，两者的体验差异很微妙，我尝试从「产品原子」的视角来分析下。

先给「产品原子」做个定义：产品原子是用户在这个产品里创建、命名、分享、归档、删除的最小单位。

用这个视角看 Agent，大致可以分成三类：

  1. 以对话为原子（session）：主界面像一条按时间倒排的聊天流水，新对话不断把旧的往下推，几周前聊过的事要靠搜索才找得回来。

  2. 以项目为原子（project）：主界面像一个文件柜，每个抽屉装着一个项目的资料、说明和一叠对话，先拉开抽屉，再在里面接着聊。

  3. 以角色为原子（bot）：主界面像一张组织架构图，每一个是有职责、有记忆的角色，和它相关的事都在同一个会话里接着聊。

产品对「原子」的不同定义，带来体验上的一系列变化，我觉得最值得关注的是「连续性」：

用 ChatGPT 时，从一个对话走到下一个对话，中间唯一不断的是我自己。我就是最大的「记忆池」。

用 Project 时，资料和指令可以写入文档，让渡了一部分记忆出去。

用 Bot 时，连续性沉淀到了一个个 Bot 身上。

（虽然每类产品，都有 Memory 功能，但同样一个词，在不同的「原子」产品中的作用差异还是蛮大的。）

关于以角色为原子的产品，如何「切分」各个 bot 的职责边界，是个很关键的课题，可以参照 Simon 在论文《The Architecture of Complexity》中提出的近可分解性（near-decomposability）：层内交互强，层间交互弱。
