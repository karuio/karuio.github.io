中文改写

生成式推荐让模型预测“用户下一个会点什么”，现在不少团队想把它往前推一步：一次预测用户接下来一连串的行为。Eric Seufert 周六早上推荐了快手的一篇论文，讲的就是这一步会遇到什么问题、怎么解决。

一连串预测，错误会层层放大

现在常见的做法是用语义 ID（semantic ID，SID）表示每个物品，让模型预测下一个物品的 SID。按 Seufert 的概括，把这种“下一个物品”的预测扩展到未来一整串交互，会出现一个问题：每一步预测都成为后续预测的上下文，前面错一步，后面跟着错；模型也只能沿一条路径走下去，用户可能有的其他行为带来的不确定性被忽略掉了。

训练方式让这个错位更严重。训练时模型看到的是用户真实发生过的交互，推理时却只能拿自己的预测当依据往下猜。

TraGR 的做法

快手研究人员提出的框架叫 TraGR。Seufert 介绍了三处设计：

  • 每个物品的 SID token 并行生成，并在相邻两次预测之间更新一个“行为状态”；
  • 往前推演时，同时带上被选中的物品，以及其他候选物品按概率加权后的汇总，不只押一条路径；
  • 监督微调（SFT）之后，用模型自己生成的行为轨迹做后训练，奖励三件事：预测准确、行为转移有历史行为支持、前面的选择有助于后续预测。

离线结果

TraGR 还没有上线到生产环境。在四个公开数据集上的离线测试中，它在所有报告的指标组合上都超过了 13 种基线配置。以 MNDCG@10 衡量的排序质量，相对每个数据集上最强的基线提升了 1.1% 到 21.4%。

这些都是论文给出的离线数字，线上效果还没有验证。论文题为《From Tokens to Behaviors: Rethinking Generative Recommendation for User Trajectory Prediction》，Seufert 在跟帖里附了 arXiv 链接。

给做推荐系统的人

如果团队正在用语义 ID 做生成式推荐，并想从预测单个物品扩展到预测行为序列，这篇论文点出的两个坑可以先对照检查：自回归预测的误差累积，以及训练用真实数据、推理用自身预测之间的错位。TraGR 的并行生成、加权候选和自生成轨迹后训练是一种应对方案，不过目前只有离线证据。

Compelling and insightful Saturday morning coffee read from Kuaishou on the ever-evolving topic of Generative Retrieval.

Compelling and insightful Saturday morning coffee read from Kuaishou on the ever-evolving topic of Generative Retrieval.

Extending next-item prediction with semantic IDs (SIDs) to a sequence of future interactions introduces a problem: each prediction becomes context for subsequent predictions, allowing errors to cascade and forcing uncertainty about alternative behaviors to be ignored. Training on observed interactions compounds this mismatch because, at inference, the model must predict on the basis of its own predictions.

To address this, researchers from Kuaishou introduce TraGR, a framework that generates each item's semantic-ID tokens in parallel, updating a behavioral state between predicted interactions. The model projects forward both the selected item and a probability-weighted summary of alternatives. Following SFT, the researchers post-trained the model with its own generated trajectories, rewarding prediction accuracy, transitions supported by historical behavior, and earlier choices that improve subsequent predictions.

TraGR isn't integrated into production, but across four public datasets in offline tests, it outperformed 13 baseline configurations on all reported metric combinations. Ranking quality as measured by MNDCG@10 improved by 1.1% - 21.4% relative to each dataset's strongest baseline.
